# Independent Mesa release checks and flashing entry point

Follow root `AGENT.md`; no local/target builds or source tests. GitHub CI performs verification. `src/lib.rs::run_update`, `run_flash`, and the two CLIs are the only public entry points; internals remain private. Do not import `app/updater` internals, depend on controller/desktop/HAL internals, or create generic utility modules. README files are maintained by humans.

- `betterlinuxcnc-mesa-update check|status|download` is only for fixed ordinary account `linuxcnc`. An independent system timer/service runs `check` as that account; the timer never downloads, stops control, or flashes. `check` queries official latest Releases of fixed `ArcAmberTeam/ArcAmberCNC` and `ArcAmberTeam/CNC-Mesa`, reporting their common version. `download` queries only `v<version>` matching the fully installed `betterlinuxcnc-qt`; arbitrary versions, addresses, paths, and command arguments are forbidden.
- `betterlinuxcnc-mesa-flash status|request|apply-system` is a separate binary/root system service. Ordinary `linuxcnc` can only start fixed `betterlinuxcnc-mesa-flash.service` through argument-free `request`; polkit permits only starting that unit. `apply-system` delegates to public argument-free `betterlinuxcnc-updater mesa-maintenance`, without reading user cache/manifests. Only explicit requests enter this flow; timers never request flashing.
- The updater maintenance entry holds the same root flock as Debian updating. It first calls fixed `prepare-system` to independently verify/download official firmware; unavailable firmware does not stop control. It then reuses public status gates, normal mask/stop, endpoint/native-lock absence checks, and fixed appliance backup. Only success starts hidden `write-system`. Each probe/write/verify/complete gets permission from the live guard through the challenge protocol on inherited FD3; the guard rechecks stopped control at each step. FD4 inherits the same flock, preventing early release to other updates if the parent fails. write-system verifies root via Linux SO_PEERCRED, parent PID, installed updater executable, and protected lock-file identity; environment variables, bare root commands, and user cache cannot forge entry. The child independently verifies the official version/bitstream again, closes original inherited fds and holds them with CLOEXEC; hardware children do not inherit the capability.
- Fixed target: `10.10.10.10`, 7I92, 6slx9tqg144, based on onsite read-only evidence. Accept no user address/board type. Static neighbor MAC 00:ff:ff:ff:ff:ff is not unique hardware identity. Factory labels or software model names do not prove physical constraints; manifest board_approved and physical_constraints_verified must both be true. Also verify Xilinx bitstream header, part, and full length. After shutdown, run only fixed `/usr/bin/mesaflash --device 7I92 --addr 10.10.10.10 --verbose` to identify unique model/address/FPGA/connectors, then user-flash `--write` and independent `--verify`. Prohibit reload, reset, program, fallback, recover, fix-boot-block, disabled automatic verification, and output enabling. CLI/output evidence comes from mesaflash.c, eth_boards.c, common.c, and eeprom.c in [LinuxCNC mesaflash](https://github.com/LinuxCNC/mesaflash/tree/11e6f8571cc79d3acae57274aa57c4b99d26cb3f). Debian supplies the tool; do not bundle/modify it.
- Write/readback failure leaves control stopped. Success also retains runtime masks and reports `programmed_pending_power_cycle`, without restarting the core, reloading the card, or claiming new firmware is running. Read kernel boot_id before writing and store it as host_boot_id. If read-only status finds a valid successful-record boot_id differs from the current host, derive `host_restarted_board_unconfirmed` while retaining original version, manifest/hash, time, and write-time boot_id without modifying disk. Missing old fields, invalid values, or unreadable current boot_id remain pending. Host restart does not prove card power cycling or new firmware operation; a new explicit request still passes all gates. Controlled power cycling, restart, and onsite acceptance require subsequent explicit maintenance. Do not hide failures by restoring services or force-killing card writes.
- Both CLIs emit schema_version=1 JSON on stdout: component, phase, message, updated_unix, host_boot_id, installed_app_version, available_version, app_latest_version, mesa_latest_version, manifest, firmware_downloaded, flash_enabled. `request` returns scheduled. Root phases include checking, verified, verifying_identity, writing, verifying, programmed_pending_power_cycle, host_restarted_board_unconfirmed, blocked, error. `flash_enabled` only indicates GUI eligibility based on installed/verified release versions; it is not shutdown/authorization evidence and is false for this firmware-free release. `firmware_downloaded` only means cache validation succeeded, never that a board was flashed or runs that version. Ordinary users use private request timestamps only to suppress stale root results; root never reads them.
- Fixed `mesa-release.json`: schema_version=1, version, tag_name, compatible_app_version, source_commit, board=zhulong-v2, variant=PIN_ZHULONG_V2_34, fpga=xc6slx9, package=tqg144, physical_constraints_verified. artifacts.source/integration each contain asset, sha256, size_bytes. firmware contains available, asset, sha256, size, origin, reason, and nested verification implementation/timing/board_approved.
- This is a valid source release: firmware.available=false, asset/sha256/size=null, origin=unavailable, and all three verification fields=false. Display “Source update, no firmware”; do not reject the whole manifest or pass off an old factory bitstream as newly built. Future available=true requires origin=ci-build, all three verifications and physical_constraints_verified=true, with matching version, board, FPGA/package, tag-resolved source_commit, official asset URL/size, and SHA-256.
- HTTPS is restricted to fixed official repositories and GitHub Release CDN. Disable environment proxies; bound response sizes, timeouts, and redirects. Do not read arbitrary URL/repository configuration or echo signed download URLs in HTTP errors. Missing assets, prereleases, unknown provenance, hash mismatch, partial installation, or unpaired versions fail closed.
- Fixed low-privilege cache: `/var/cache/betterlinuxcnc/user/mesa-update`; root cache: `/var/cache/betterlinuxcnc/mesa-flash`; root public result: `/var/lib/betterlinuxcnc/mesa-flash/status.json`. Ordinary users cannot write root parents. Open directories component-by-component using fds and O_NOFOLLOW and verify ownership/permissions: cache 0700, files 0600, public directory 0755/status 0644. Use separate locks, fsync, and atomic renames; do not follow links or read special/hardlinked cache state.
- CMake independently installs two binaries and three exact system units. Packages do not enable/start the timer or flash service; explicit appliance activate enables the check timer. Root flash must see real /tmp/native locks, so no PrivateTmp. Retain limited capabilities needed for runuser privilege reduction and backup reads. Do not impose these restrictions on the full real-time launcher. Update updater package allowlists for new install paths.
- CI runs cargo fmt --check, cargo check --locked --all-targets, cargo clippy --locked --all-targets -- -D warnings, and cargo test --locked. Cover original-byte official manifest fixtures, argument boundaries for both public processes, version pairing, source-only releases, source commits, official URLs, hashes, independent root requests, cache links, actual inherited fds/process exits, missing/out-of-order guards, backup failure, identity mismatch, and write/readback failure. Use controlled HTTP adapters and temporary executable substitutes, never real network, machines, or mesaflash.
- Root maintenance units also retain limited SETUID/SETGID/DAC_READ_SEARCH through AmbientCapabilities so NoNewPrivileges with User=root does not lose actual privilege-reduction ability. GitHub's real systemd sandbox verification runs only runuser/id, never maintenance entry points or flashing.
