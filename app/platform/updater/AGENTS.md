# Rust Release update service

Follow root `AGENT.md`. `src/lib.rs::run` and the `betterlinuxcnc-updater` CLI are public entry points; internals are private. The module does not depend on CAM, Qt, Python application implementation, HAL, or LinuxCNC extensions.

- Ordinary `linuxcnc` has no sudo/root privileges. The GUI may query, download, and trigger fixed `betterlinuxcnc-system-update.service`; installation accepts no package path, URL, version, socket, or APT options. polkit permits linuxcnc only to start this unit and independent `betterlinuxcnc-mesa-flash.service`, without other systemd management or pkexec privileges.
- Only the system unit invokes root broker `apply-system`. It independently queries the official latest Release of fixed ArcAmberTeam/ArcAmberCNC, downloads again, and verifies SHA-256, Debian package name/version/architecture, and anti-rollback. Never install from user cache/manifests. External commands use fixed absolute paths and sanitized environments; networking disables environment proxies.
- `/etc/betterlinuxcnc/updater.json` contains only `user=linuxcnc` and `config=/etc/betterlinuxcnc/launcher.json`. Check both files and every parent for root ownership, no group/other write permission, and no symlinks. Root cache, lock, and installation logs live in `/var/cache/betterlinuxcnc/update`; public read-only JSON state is `/var/lib/betterlinuxcnc/update/status.json`. Both top-level parents remain root-owned; account HOME/user cache live in separate children.
- Parse package content as a stream through fixed dpkg-deb and standard-library tarfile under python3 -I -S; never extract and execute it. Accept only existing application system commands, application lib/share/doc subtrees, and individually allowed integration files. Reject traversal, all links, special nodes, unsafe permissions, and unknown control files. New install paths require allowlist and positive/negative-test updates.
- The independent Mesa module adds only exact commands `betterlinuxcnc-mesa-update`, `betterlinuxcnc-mesa-flash`, their two same-named system `.service` units, and check timer `betterlinuxcnc-mesa-update.timer`. Do not permit flash timers, arbitrary mesaflash binaries, or extra system configuration. Firmware validation/future flashing belongs to `app/platform/mesa-update`; this updater must not import its internals.
- Also permit exact `/usr/lib/linuxcnc/modules/zhulong_homing.so`, without opening the directory or allowing other native modules to be replaced. The independent homing adapter owns provenance and core/dev ABI validation.
- Fixed public argument-free `mesa-maintenance` is for the root service only. It shares the APT root update lock, invokes independent Mesa CLI `prepare-system` to verify official firmware, reuses safe-state gates, normal shutdown, and fixed backup, then starts the sole `write-system`. FD3 carries random challenges and stepwise probe/write/verify/complete authorization; FD4 inherits the same flock. Every step reconfirms control socket/native lock absence. The parent grants no authority through environment variables, arbitrary commands, user paths, or continued operation after unlocking. Backup failure creates no writer. After stopping, retain runtime masks; even successful readback does not restart/reload the card. Report that controlled power cycling is pending; hardware implementation remains with Mesa.
- The only permitted maintainer script is `postinst`, byte-identical to `src/updater/package_members.py::APPROVED_POSTINST`, root:root and 0755. Its `configure` branch only executes fixed `/usr/sbin/betterlinuxcnc-appliance provision`, idempotently setting accounts/fixed directory permissions and invoking the user-authorized fixed v1 XYZ migration with exact hashes, stopped core, verified module, and atomic directory exchange. It does not change passwords, SSH, desktop sessions, or start the machine. Reject all other scripts or byte changes. `tools/appliance/packaging/postinst` is the packaging entry; CI must compare both copies. Keep these bytes stable long-term, including LF and final newline; provision upgrades must not rewrite it or old installed updaters will reject future packages. sysusers/tmpfiles and other new system paths are not approved.
- Before installation, read public `machine.status`; reject unknown, paused, moving, queued-job, running-spindle, or enabled states. Root connects read-only to the fixed account's private socket. User systemd operations use fixed runuser with privilege reduction and sanitized environment. Recheck before stopping, temporarily mask the launcher, and stop normally. Reject installation while control endpoints/native locks remain or if the user session cannot be queried.
- The fixed root unit explicitly retains CAP_SETUID/CAP_SETGID ambient capabilities so User=root, NoNewPrivileges, and sandboxing still permit dropping to linuxcnc. The ordinary account does not receive these capabilities. GitHub-hosted runners verify actual systemd restrictions and runuser/id; a systemctl substitute alone cannot establish acceptance.
- After normal launcher shutdown and release of control socket/native locks, execute fixed `/usr/sbin/betterlinuxcnc-appliance backup` with a sanitized environment before APT. Only successful backup permits APT. appliance independently owns backup of fixed machine configuration, mutable state, and host policies into root-private snapshots; no GUI-supplied source/destination paths or commands. Failure to start backup or a failing exit rejects installation and leaves control stopped.
- Never report failure as success or automatically start a possibly mixed-version control stack. Restore a previously running managed launcher only after APT succeeds and installed version is rechecked. Do not grant the GUI firmware, INI/HAL, arbitrary-file, or system-command write access.
- Tests use temporary directories, release metadata, real Unix sockets, and controlled processes, without real machines, real installation, or publishing Releases. Under current user requirements, run cargo fmt --check, cargo check --locked --all-targets, cargo clippy --locked --all-targets -- -D warnings, and cargo test --locked only in GitHub CI, never locally/on target. Real Debian archive regression must accept the fixed postinst and reject altered content/other scripts without executing package scripts. README files are maintained by humans.
