# Rust system service boundaries

Follow the root `AGENT.md`. README files are maintained by humans.

- `run` in `src/lib.rs` and installed binary `betterlinuxcnc-cam-link` are the public entry points. `cam_link` internals are private. This module owns only CAM integration; other applications belong in sibling modules by responsibility, not the diagnostics library or Python package.
- CAM Link owns TCP 6522, optional UDP 8421 discovery, its separate inbox, status subscriptions, and network connection lifecycles. It does not load Python, create LinuxCNC/NML/HAL channels, or start/supervise other processes. Startup order and process supervision belong to `app/launcher`.
- `protocol` owns CAM2 framing and strict JSON; `inbox` owns file validation and atomic publication; `control` adapts only the public v2 Unix protocol; `manual` manages jogging leases through control; `feedback` reads status through control and associates files through inbox; `discovery` owns the bounded UDP handshake; `transfer` only receives files; `homing` submits independent homing; `wf-transhoming.rs` submits the combined workflow; `session` dispatches capabilities. Reverse dependencies and exposing internal types for tests are forbidden.
- Default one-click direct connection uses empty-parameter `session.auth`. Enable tokens/TLS only when explicitly configured; authentication failure must never cause automatic downgrade. UDP carries no tokens, files, or machining state; discovery does not grant control.
- Uploads and receipts always concern files only and never trigger motion, even with `--auto-run`. That option only permits explicit `home.start`, `job.start`, and `workflow.start`; callers must explicitly confirm homing clearance and combined-workflow readiness. The Controller owns the workflow's homing → machining sequence, cancellation, and persistence; Rust must not assemble motion through polling. Status and cancellation are not restricted by the network-start switch. Lost responses mean unknown; do not scan/resume work on restart or retry automatically.
- XYZ jogging uses `cam.jog.start/keepalive/stop` on the same connection. The 450 ms network lease is separate from the controller's 600 ms lease. Expiry, disconnect, stop, and service shutdown must close the corresponding Unix connection; do not renew in the background or preempt the desktop.
- Run disk uploads in the blocking task pool so they cannot delay jogging timers. Only the Upload lifecycle cleans incomplete directories; published files must not be overwritten.
- Tests use real Rust CLI, TCP/UDP/Unix sockets, and public Python service entry points. Vendor substitutes come from test directories; do not start machines or simulators. Python is used only as a test client and the existing local controller service, not as the CAM network service.
- In this directory, run `cargo fmt --check`, `cargo check --locked --all-targets`, `cargo clippy --locked --all-targets -- -D warnings`, and `cargo test --locked`; cross-process tests require Python 3.11+ (`SERVICE_TEST_PYTHON`). Test Python follows Ruff rules from `app/controller/pyproject.toml`.
