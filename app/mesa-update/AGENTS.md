# 独立 Mesa 发布检查与烧录入口

遵循根 `AGENT.md`；本地及目标机不构建、不运行源码测试，验证由 GitHub CI 执行。`src/lib.rs::run_update`、`run_flash` 和两个 CLI 是唯一公开入口，内部模块不对外开放。不导入 `app/updater` 私有实现，不依赖控制服务、桌面或 HAL 的内部代码，不建立通用工具模块。README 只由人工维护。

- `betterlinuxcnc-mesa-update check|status|download` 仅供固定 `linuxcnc` 普通账户使用。独立系统 timer/service 以该账户执行 `check`；timer 不下载、不停机、不烧录。`check` 查询固定 `ArcAmberTeam/ArcAmberCNC` 与 `ArcAmberTeam/CNC-Mesa` latest 正式 Release，报告共同版本。`download` 只查询已完整安装的 `betterlinuxcnc-qt` 版本对应的 `v<version>`，禁止任意版本、地址、路径或命令参数。
- `betterlinuxcnc-mesa-flash status|request|apply-system` 是另一个独立二进制和 root 系统服务。普通 `linuxcnc` 只能用零参数 `request` 启动固定 `betterlinuxcnc-mesa-flash.service`；polkit 仅允许这个 unit 的 start。`apply-system` 委托公开、零参数的 `betterlinuxcnc-updater mesa-maintenance`，不读取用户缓存或用户 manifest。只有显式请求才能进入该流程，timer 永远不请求刷写。
- updater 维护入口持有与 Debian 更新共用的 root flock；先调用固定 `prepare-system` 从官方重新验证下载，固件不可用时不停止控制系统。之后复用既有公开状态门禁、正常 mask/stop、端点和原生锁消失检查、固定 appliance backup，成功才启动隐藏的 `write-system`。每次 probe/write/verify/complete 都通过继承 FD3 的挑战协议取得存活 guard 的放行，guard 逐步复核控制系统仍停止。FD4 继承同一 flock，父进程异常退出也不提前放开其他更新。write-system 验证 Linux SO_PEERCRED 的 root、父 PID、已安装 updater exe、受保护锁文件身份；环境变量、裸 root 命令或用户缓存均不能伪造此入口。子进程再次独立验证官方版本/位流，关闭原始继承 fd 并以 CLOEXEC 持有，硬件子进程不继承 capability。
- 固定目标 `10.10.10.10`、7I92、6slx9tqg144（现场只读证据）；不接受用户输入地址或板型。不把静态邻居 MAC 00:ff:ff:ff:ff:ff 当作唯一硬件身份。原厂板卡标签或软件型号本身不证明物理约束，仍须 manifest 的 board_approved 和 physical_constraints_verified 全真。位流另核对 Xilinx header、part 和完整长度。停止后仅执行固定 `/usr/bin/mesaflash --device 7I92 --addr 10.10.10.10 --verbose` 识别唯一型号/地址/FPGA/连接器，再执行 user flash 区的 `--write` 与独立 `--verify`。禁止 reload、reset、program、fallback、recover、fix-boot-block、禁用自动校验或输出使能。CLI/输出依据为 [LinuxCNC mesaflash](https://github.com/LinuxCNC/mesaflash/tree/11e6f8571cc79d3acae57274aa57c4b99d26cb3f) 的 mesaflash.c、eth_boards.c、common.c、eeprom.c；Debian 依赖提供工具，不捆绑或修改它。
- 写入或回读失败保持控制停止；成功也保留 runtime mask，报告 `programmed_pending_power_cycle`，不重启核心、不自动重载卡、不声称新固件已运行。写入前读取内核 boot_id 并作为 host_boot_id 保存在操作记录。只读 status 发现成功记录的有效 boot_id 与当前主机不同时，派生 `host_restarted_board_unconfirmed`，保留原版本、manifest/摘要、时间和写入时 boot_id，不改磁盘；缺旧字段、无效值或当前 boot_id 不可读时继续 pending。主机重启不证明板卡已断电或新固件已运行；新显式请求仍须经过全部维护门禁。受控断电、重新启动与现场验收是后续显式维护步骤。不要通过恢复服务或强杀卡写入过程掩盖故障。
- 两个 CLI stdout 使用 schema_version=1 JSON：component、phase、message、updated_unix、host_boot_id、installed_app_version、available_version、app_latest_version、mesa_latest_version、manifest、firmware_downloaded、flash_enabled。`request` 返回 scheduled；root 阶段包含 checking、verified、verifying_identity、writing、verifying、programmed_pending_power_cycle、host_restarted_board_unconfirmed、blocked、error。`flash_enabled` 只是已安装版本与已验证发布的 GUI 资格提示，不是停机或权限凭据；本版无固件所以为 false。`firmware_downloaded` 只说明缓存通过验证，绝不代表板卡已刷或其运行版本。普通用户只用私有 request 时间记录屏蔽旧 root 结果；root 不读取该记录。
- 固定 `mesa-release.json`：schema_version=1、version、tag_name、compatible_app_version、source_commit、board=zhulong-v2、variant=PIN_ZHULONG_V2_34、fpga=xc6slx9、package=tqg144、physical_constraints_verified；artifacts.source/integration 各含 asset、sha256、size_bytes；firmware 含 available、asset、sha256、size、origin、reason 和嵌套 verification 的 implementation/timing/board_approved。
- 本版为合法源码发布：firmware.available=false、asset/sha256/size=null、origin=unavailable、三项验证=false。必须显示“源码更新、无固件”，不拒掉整个 manifest，也不能用原厂旧 bit 冒充新构建。未来 available=true 必须 origin=ci-build、三项验证及 physical_constraints_verified 全 true；版本、板卡、FPGA/package、tag 解析后的 source_commit、官方 asset URL/size 与 SHA-256 都需匹配。
- HTTPS 仅访问固定官方仓库与 GitHub Release CDN；禁用环境代理，限定响应大小、超时和重定向，不读取任意 URL 或仓库配置。HTTP 错误不回显签名下载 URL。缺失资产、预发布、来源不明、摘要不符、部分安装或版本不配对均失败关闭。
- 低权限缓存固定 `/var/cache/betterlinuxcnc/user/mesa-update`，root 缓存固定 `/var/cache/betterlinuxcnc/mesa-flash`，root 公开结果固定 `/var/lib/betterlinuxcnc/mesa-flash/status.json`。root 父目录不能由普通账户写入。目录逐层用 fd 和 O_NOFOLLOW 打开并检查属主/权限，缓存 0700、文件 0600，公开目录 0755/status 0644。使用独立锁和 fsync/原子改名；不跟随链接、特殊文件或硬链接读取缓存状态。
- CMake 独立安装两 bin 和三个精确 system unit。安装包不启用/启动 timer 或 flash；appliance 显式 activate 启用检查 timer。root flash 必须看得到真实 /tmp/native lock，不设置 PrivateTmp；保留 runuser 降权和备份读取所需的限定 capabilities。不将这些限制施加到完整实时启动器。新增安装路径同步更新 updater 包边界白名单。
- CI 应执行 cargo fmt --check、cargo check --locked --all-targets、cargo clippy --locked --all-targets -- -D warnings 和 cargo test --locked。测试覆盖原字节正式 manifest fixture、两公开进程参数边界、版本配对、source-only、源提交、官方 URL、摘要、root 独立请求、缓存链接、真实继承 fd/进程退出、guard 丢失/乱序、备份失败、型号不符及写入/回读失败；使用受控 HTTP 适配和临时可执行替身，不访问真实网络、机床或 mesaflash。
- root 维护单元的限定 SETUID/SETGID/DAC_READ_SEARCH 同时通过 AmbientCapabilities 保留，避免 NoNewPrivileges 与 User=root 的组合丢失实际降权能力。GitHub 的真实 systemd 沙箱验证仅运行 runuser/id，不启动维护入口或执行烧录。
